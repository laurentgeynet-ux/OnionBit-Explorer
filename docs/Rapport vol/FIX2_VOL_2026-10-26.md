## Par constat

### 1. HAUTE — `<#comment>` peint à l'écran

**Reproduit ?** Non nécessaire — mécanisme localisé avec
certitude, mais **hors de mon périmètre**.

**Diagnostic** : les commentaires sont corrects dans
`explorer-html` (`insert_comment` partout dans `tree.rs`)
et `explorer-layout` ne boxifie jamais `NodeData::Comment`
(test `commentaire_ne_peint_pas`, `boxtree.rs:574`).
Le nœud texte `"<#comment>"` vient de la sérialisation
**cléée** du miroir JS :
`crates/explorer-jscore/src/dom.rs`,
`serialize_keyed_node` (~l.1043, bras `Ser::Enter`) gère
`NodeKind::Text` et `NodeKind::Fragment` mais **pas
`NodeKind::Comment`** — contrairement à `serialize`
(non cléée, l.3205) qui émet `<!--…-->` correctement.
Un commentaire miroir (créés en masse par Lit —
`?lit$N$` — et par `document.createComment`,
`parse_fragment_into` les émet aussi) tombe donc dans
le chemin générique : `tags.push("#comment")` + émission
de `<#comment>…</#comment>`. Au re-parse moteur, `<#`
n'est pas une balise valide → **texte littéral
`<#comment>`** — exactement ce qui est peint sur
old.reddit, archive.org, w3.org, ecma.

**Fix à appliquer (agent jscore)** : dans
`serialize_keyed_node`, bras `Ser::Enter`, sauter les
commentaires **sans pousser id ni tag** — le contrat
`serializable_kind` côté `explorer-core`
(`apply.rs:745`, « le miroir n'a ni doctype ni
commentaire ») attend exactement ça : pousser le
commentaire en ids/tags désalignerait l'appariement
par tag du rejeu journal.

### 2. HAUTE — `<noscript>` affiché sous scripting

**Reproduit ?** Oui, indirectement : sur mastodon le
`block<noscript>` du layout dump est `display:flex` —
la feuille auteur `themes/default-*.css` porte
`noscript{display:flex;…}`, qui écrasait la règle UA
`@media (scripting) { noscript { display:none } }`.
**La spec HTML Rendering rend cette règle
`display: none !important`** (vérifié en ligne).

**Fixé ?** Oui — commit `e8c2ef0` : `!important` ajouté
dans `UA_CSS` (`cascade.rs:2296`) ; l'important UA
coiffe l'auteur normal ET l'auteur important (ordre
déjà implémenté). Le parse rawtext était déjà correct
(dumps : contenu en texte verbatim).

**Tests** : `noscript_important_coiffe_style_auteur`
(cascade.rs — flex auteur normal + `!important` auteur
cédés, flex appliqué sans scripting). Suite
`explorer-css` entière verte (106+103+16+14 tests).

### 4. MOYEN — hit-test `<input>` (`editable:false`)

**Reproduit ?** Non — sur le dump service-public, le
point naturel du champ ne touche **que** la chaîne
`form > input` (aucun overlay) : le mécanisme
(`hit_test` → `editable_field` → `type∈TEXT_TYPES`,
`search` inclus) aurait répondu `editable:true`. La
cause terrain la plus plausible, confirmée comme trou
réel : **`pointer-events` n'était pas honoré** — un
overlay auteur `pointer-events:none` couvrant le champ
volait la cible (`editable:false`, clic `ignored`).

**Fixé ?** Oui — commit `727984d` : `unhittable()`
dans `hit.rs` combine `visibility:hidden|collapse` et
`pointer-events:none` ; on descend quand même (un
enfant `auto` explicite reste ciblable — valeur
calculée distincte, conforme spec).

**Tests** : `hit_test_pointer_events_none_transparent`,
`hit_test_pointer_events_enfant_reactive` (block.rs).
**Reste** : si le constat agent avait une autre cause
(coords exactes non fournies), rouvrir — instrumentation
`tracing::debug` hit-test déjà en place
(`node_at`, input.rs).

### 7. BASSE — SVG géant/écrasé

**Reproduit ?** Oui par inspection :
`svg_intrinsic` (`boxtree.rs:1058`) retournait la
taille du `viewBox` quand `width`/`height` manquaient
— un `<svg viewBox="0 0 1024 …">` occupait ~1024 px
(logo w3.org géant). Spec SVG2 : attribut absent =
`auto` = `100%` du conteneur.

**Fixé ?** Oui — commit `bf2b0d3` : le hint de
présentation pose `width:100%` quand l'attribut
`width` manque **et** qu'un `viewBox` définit la
géométrie (sans viewBox → repli 300×150 inchangé) ;
`height:auto` dérive du ratio intrinsèque (§10.6.2,
déjà câblé). Attributs explicites intacts.

**Tests** : `svg_viewbox_seul_occupe_la_largeur_
conteneur` (400×200), `svg_dimensions_explicites_
inchangees` (80×40).
