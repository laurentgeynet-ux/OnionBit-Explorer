## Constat 1 — HAUTE : onglet parasite sur URL `.js` (rakuten)

- **Reproduit ?** Par analyse de code : `download_meta`
  (`net_items.rs`) classait `text/javascript` en `doc_like`
  (`text/*`) → un `window.open`/`target=_blank` vers un `.js`
  servait la source brute dans un onglet neuf. Couvert par test.
- **Fixé ?** Oui, deux volets :
  1. `download_meta` exclut les types script
     (`text|application/javascript`, `*/ecmascript`,
     `text/jscript`, `text/livescript`, `text/x-*`) → offre de
     téléchargement, comme les navigateurs.
  2. `Session::close_stillborn_popup` (`mod.rs`) : un contexte
     `NewTab` resté vierge (`url: None`, `hist` vide) après sa
     navigation inaugurale est refermé ; pendings ré-attribués à
     l'opener. Branché dans `drain_script_nav` (navigate.rs) et
     `drain_navs_shared` (shared.rs).
- **Commit :** `854d554 fix(core): onglet parasite sur navigation
  vers une ressource .js`
- **Tests :** `download_meta_rejects_script_mimes`,
  `stillborn_popup_closes_and_downloads_reattributed` (verts).
- **Reste :** l'événement `DownloadOffered` d'une popup mort-née
  porte l'ancien `TabId` (borne documentée) ; un `.js` servi
  `text/plain` resterait affiché — correct (sniffing honeste).

## Constat 2 — HAUTE : crash daemon silencieux (vol 4)

- **Reproduit ?** Non (non reproduit en vol non plus).
- **Audit :** tous les chemins DELETE/navigate concurrents sont
  gardés (`Option` + epoch) : `close_tab` aborte les `net_tasks`,
  `commit_js_pump`/`take_nav_paint`/`commit_nav_paint`/
  `reclaim_orphaned_paint`/`offer_download` traitent l'onglet
  absent sans panic. Zéro `unwrap/expect/panic` dans le code livré
  de `explorer-core`/`explorer-api`/`explorer-daemon`. La
  sentinelle `EXPLORER_DEATH_LOG` + hook panic + piles 32 Mio
  existent déjà (main.rs) : un `alive` résiduel = mort sans
  crochet Rust → kill externe, stack overflow ou **alloc-abort
  (OOM)** — cohérent avec ~526 Mio retenus après 5 navigations
  (constat 4, corrigé) et la croissance mémoire de la station.
- **Fixé ?** Indirectement : le poste mémoire dominant
  adressable dans notre périmètre (rasters bfcache) est réduit.
- **Reste :** si le crash réapparaît, `explorer_daemon_death.log`
  tranchera « panic nommé » vs « mort externe » ; candidat
  restant : récursion layout/DOM sur hôte hostile (périmètre
  FIX-2) ou OOM réel.

## Constat 5 — BASSE : meta-refresh dans `<noscript>` non suivi

- **Analyse :** scripting levé au parse (CAP-155), le contenu
  `noscript` est rawtext — la méta n'existe pas dans le DOM ;
  spec : ignorée tant que le scripting tourne.
- **Fixé ?** Repli produit `noscript_meta_refresh`
  (`dom_helpers.rs`) : quand le `body` est un **fallback pur**
  (enfants éléments = `noscript`/`script` seulement, aucun texte
  non blanc), le rawtext est re-parsé scripting off et sa méta
  refresh honorée — sens exact du repli google SERP
  (`/httpservice/retry/enablejs`). Une page riche avec un
  `noscript` annexe garde la spec (`None`). Branché en
  `.or_else` sur `NavJob::run` et `decline_download`.
- **Commit :** `8d9a9ee fix(core): meta refresh en <noscript>
  honorée sur page de repli pur`
- **Test :** `noscript_meta_refresh_fallback_pure_only` (vert).
- **Reste :** un site dont le fallback pur mène à une boucle
  retombe sur le budget `max_auto_navs` (étape 144) — borné.

## Constat 1 — HAUTE : iframes jamais chargées (tumblr CMP)

- **Investigué :** le pipeline existe de bout en bout —
  `plan_subresources` collecte les `<iframe src>` (borne
  `max_frames: 8`), `sub_jobs` émet `SubTag::Frame` à la
  vague (`fetch_wave`), `collect_frame` → `store_frame` →
  `SubFrame` → `composite` blitte la surface ; `srcdoc` et
  cadres dynamiques JS ont leurs chemins propres. Le cadre
  blanc du CMP est donc le refus d'embarquement
  (X-Frame-Options / `frame-ancestors` — spec-correct, un
  navigateur afficherait aussi un cadre vide) ou un fetch
  en échec — **les trois issues étaient muettes**.
- **Fixé ?** `tracing::warn` posé sur : fetch en échec,
  statut non-2xx, refus d'embarquement (`collect_frame`).
  Le prochain vol pourra nommer la cause réelle.
- **Commit :** `c420ae6` (avec constat 2).
- **Reste :** si le warn montre un refus, c'est un
  comportement voulu — sinon le dump dira lequel.

## Constat 2 — HAUTE : console perdue après navigation JS

- **Cause trouvée :** `event_capacity = 64` — le bus
  broadcast porte toutes les variantes (`Navigated`,
  `FrameInvalidated`×N, `TabOpened`…) ; une navigation
  émet un burst >64 événements → le recorder console
  (abonné par `recv()`) passe en `Lagged` et les
  `PipelineError` du nouveau document sont **jetés
  définitivement** — exactement « ring vide après nav ».
- **Fixé ?** `event_capacity` 64 → 512 (`types.rs`) —
  dimensionné pour le burst d'une navigation complète.
- **Commit :** `c420ae6 fix(core): console perdue après
  navigation + iframe échecs logués`
- **Reste :** un burst >512 (page très bruyante) peut
  encore lagguer — le recorder reste best-effort par
  conception (SSE/pull couvrent le reste) ; à ré-étalonner
  au prochain vol.

## Constat 3 — MOYEN : `/frame` incohérente (IGN viewport,
