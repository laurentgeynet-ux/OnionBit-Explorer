## 2. Excalidraw — « 'in' requires an object » — FIXÉ

- **Diagnostic** (bundle réel, `index-BboF1hDf.js:56:3506`) :
  `Dr(e,t,n)` = instrumentation Sentry ; le coupable est
  `Dr(XMLHttpRequest.prototype, "send", Jhe)` — `XMLHttpRequest`
  existait mais `.prototype` valait `undefined`.
- **Fix** (`src/xhr.rs` + `interp/mod.rs` + `context.rs`) :
  vrai `XMLHttpRequest.prototype` (objet), méthodes
  `open/send/abort/setRequestHeader/getResponseHeader/
  getAllResponseHeaders/overrideMimeType/addEventListener/
  removeEventListener` posées en bound `hostMethod`
  (re-dispatch `Host::invoke` sur le receveur) → `xhr.send`
  lisible comme fonction, `"send" in proto` vrai,
  `xhr instanceof XMLHttpRequest` vrai, constantes
  `UNSENT…DONE` sur ctor et proto, proto chaîné aux instances,
  racine GC (`xhr.xhr_proto`).
  Limite : `xhr.send()` direct dispatche `Host::invoke` en
  premier — l'override JS du proto est contournée pour les
  appels directs (dégradation documentée, pas de crash).
- **Commit** : `45a6612 fix(jscore): JS-C135`.
- **Test** : `vol1_xhr_prototype_instrumentable`.
- Le même motif `in requires an object` sur bookshop.org
  (Astro/Sentry) est probablement couvert par ce fix.
